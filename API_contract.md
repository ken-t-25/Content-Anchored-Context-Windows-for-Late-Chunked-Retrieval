# Encoding and experiment contract

- **Retrieval identity.** A document has ordered stable chunk IDs, original text per chunk, and token spans in a wrapped model input. A comparison uses the same eligible corpus, ordered retrieval chunks, queries, relevance labels, encoder, and scorer for all policies. Native chunks retain their supplied IDs and numeric suffix order. A document ineligible for one compared policy is excluded once for all policies with a reason and coverage counts.
- **Text and edits.** Text is the source for replacement and insertion tokenization. Tokenize edited text without truncation or implicit specials, preserve retained chunk IDs and token spans, and verify same-length replacements. Include special tokens once per wrapped contextual input. Synthetic edits measure refresh cost unless the relevance labels have been audited for the resulting text.
- **Pooling.** Pool the target retrieval spans after shifting them into the encoder input. Prefixes, neighboring spans, and special tokens provide context for aligned study encodings. The SciFact reproduction keeps its documented standalone Independent pooling convention and reports it separately. Freeze the pooling convention across development and test runs.
- **Limits.** Require positive batch sizes and legal window/overlap values before encoding. Whole-document Late uses one forward sequence per eligible document. An oversized chunk may run alone if it fits the model. The matched study wraps each Long Late window and restarts positional windows around oversized singletons. Shared prefixes and special tokens count toward context capacity. Inputs beyond the model limit raise a clear error when invoked directly. The experiment runner screens them once for all compared policies. No evidence is truncated or silently encoded with a different policy.
- **Cache.** The inference identity combines the encoder and tokenizer version or instance scope with the exact wrapped model inputs. Pooling identity also contains the target spans and ownership. Prompts or prefixes are part of the actual token inputs. Share one inference for identical input sequences and pool them using each required span. Reuse and write vectors by stable IDs. On a version change, discard stale inference and pooled values. A tokenizer migration also requires rebuilding the tokenized chunks from source text. Fresh Sticky verification uses its saved group assignments.
- **Measurements.** Report the actual batch settings and configuration, dataset/chunk/query fingerprints, model and tokenizer provenance, and the evaluation level. Standalone policy timings cover their own work. Time shared runs separately. Report refresh tokens, encoder calls, written and deleted vectors, and regrouping, encoder, and write times separately. Compare Long Late at the named context cap and record overlap. Label smoke and exploratory results. Select settings on development data, record the frozen settings for held-out evaluation, and retain per-query metrics for source-document inference.

## Ownership and interfaces

- Encoding worker owns `latechunk/encoding.py` and dedicated tests. Keep the existing encoding entry points. `Encoder` accepts optional `model_revision` and `tokenizer_revision` keyword arguments and exposes `model_name`, `model_revision`, `tokenizer_revision`, and `code_revision` for provenance. Expose `validate_long_window(window, overlap, max_length, special_tokens="raw")`. Use `long_window=None` for Full Late with strict overflow rejection. Prefer tokenizer template offset detection over deriving the offset from the first span.
- Refresh worker owns `latechunk/anchored.py`, `latechunk/sticky.py`, `latechunk/group_encoding.py`, `latechunk/positional_refresh.py`, `scripts/pilot_anchored.py`, and their dedicated tests. Preserve `AnchoredGroups`, `StickyGroups`, `PositionalRefresh`, and `RefreshStats` entry points. Expose `encoder_cache_identity(encoder)` from `latechunk/group_encoding.py`. Share grouped forward inference across distinct pooling spans. Keep `scripts/pilot_anchored.py` for corrected matched edit checks, including `--long-window` and `--long-overlap`.
- Experiment worker owns new experiment infrastructure, the experiment CLI and its dedicated tests, plus `scripts/compare_anchored.py`, `scripts/reproduce_late_chunking.py` and `latechunk/data.py` if needed. Use policy names `naive`, `naive_prefix`, `late`, `long_late`, `local_contextual`, `sticky`, `content_anchored`. Import refresh APIs across worker branches after merging. For the missing stateless policies the integrator supplies `latechunk/study_refresh.py` with `build_stateless_units` and `StatelessRefresh`. Coordinate that interface before dependent edits.
